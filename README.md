# OSE SHOGI

オセロ将棋

OSE SHOGI（オセロ将棋）は、将棋にオセロの「挟むと敵駒が味方になる」ルールを加えた無料のブラウザゲームです。

[ゲームを遊ぶ](https://oshogi-games.pages.dev/)

このリンクは公開版です。`main`へのマージ後、Cloudflareのデプロイが成功すると更新されます。作業ブランチへのマージだけでは公開版は変わりません。未公開の変更はローカルプレビューで確認してください。

画面はCloudflare Pages、友人対局のAPIは既存のWorkers・D1を使います。[旧URL](https://othello-shogi.oshogi-games.workers.dev/)も既存の参加リンクや保存したAI対局のため継続しています。ブラウザ内の保存と参加情報は新URLへ自動では引き継がれません。

## ルール
- 移動・駒打ちの直後、縦横斜め8方向で隙間なく挟んだ敵駒を反転。成りと位置を維持します。
- 王を取る、または挟んで反転すると勝利。王手への対応義務はありません。
- 新規対局のオセロジャッジ（手数による判定）は廃止しました。長期戦への仕掛けは盤面崩壊に統合しています。過去の棋譜の判定結果は引き続き読み込めます。
- 999手までは続行し、1000手目で勝敗が決まらなければ引き分けです。1000手目の王取り・反転・盤面崩壊による決着は、その勝敗を優先します。持ち駒使用の可否は開始前に選べます。

- 盤面崩壊は指定手数で予告のみを表示し、その手では生成も破壊もしません。次の手から、着手ごとに敵味方の盤上の駒からランダムに1枚を破壊。王が壊れた側は負けます。
- 遊べるチュートリアルは各陣営の王が1枚。王取り・王の反転で勝利演出を表示します。崩壊の練習は149手から穴熊を相手に始まり、150手目の予告のみを経て、相手の応手を挟み、5回の破壊、龍・馬の降臨、王の破壊を順に体験できます。

## 機能

設定から白黒の石スキンとBGMのオン・オフを選べます。BGMはElectrodoodle（Kevin MacLeod、CC BY 4.0）で、初回オン時だけ約1.3MBを読み込みます。クレジットは設定の謝辞と [音楽の利用条件](dist/music/CREDITS.txt) にあります。

終局後の「盤面で振り返る・共有」で、一手ずつの前後移動、共有URL・Xの投稿画面・棋譜ファイルの保存、オセショ様の局面評価グラフ（探索なし）を利用できます。AI対局の棋譜は端末内、友人対局は閲覧時に一度だけAPIから取得し、共有先はURL内の圧縮データから再生します。参加情報は共有しません。新しい棋譜記録は最大4096局面を保存し、更新前の対局やそれを超える長い対局は途中からの記録と表示します。

報酬型広告のローカルテストと、視聴完了コールバックで無限オセショ様を有効にする処理を実装しています。実広告はAdSense・H5 Gamesの承認後に接続します。[残りの広告設定](docs/reward-ads.md) を参照してください。

設定の「外観」で、改善版／前の改善版／前回の試作版／従来版とライト／ダークを切り替えられます。選択はそのブラウザ内に保存され、対局の状態やAIには影響しません。動画版チュートリアルは廃止し、駒を動かす練習を残しています。

画面設計の方針は [DESIGN.md](DESIGN.md)、変更前のファイルは `design-archive/` に保存しています。[最初の画面からの比較画像](dist/design-comparison/design-evolution.jpg)も参照できます。比較ページはローカル用で、公開サイトには含めません。

「対局を離れる」は、対局中なら投了してロビーへ戻り、部屋を閉じます。AI対局はブラウザ内の保存データを即削除し、友人対局の参加待ちの部屋も即削除します。友人対局は相手へ終了結果を届けるため1分だけ残し、その後はアクセス不可になります。期限切れデータはアクセス時と5分ごとの清掃で削除します。閉鎖通知を受けた画面は定期通信を停止します。部屋を閉じる前の通常の再試合機能は使えます。

AI対局（4段階）、友人との招待リンク対局、振り駒、合意による待った・再試合、木目／深緑の盤テーマ。
全難易度で0.5／1／3／5秒の思考時間に対応し、Web Workerで探索します。

AI対局はブラウザ内で完結します。作成・着手・オセショ様・待った・再試合・再読み込みで対局APIを呼びません。局面はこのブラウザに7日間保存し、`#ai=…` のURLから復帰できます。他の端末には引き継げません。保存を拒否された場合は警告を表示し、そのページを開いている間だけ保持します。旧AIの `#room=…` は初回の取得1回でローカル対局へ移行します。

友人対局は相手番・参加待ち・終了後は2秒、自分の手番は8秒、非表示中は10秒を目安に確認します。時計の期限が近い場合は早めに確認し、画面へ戻った時や回線復帰時も再確認します。変化がなければ盤面の本文を返さず、失敗時は間隔を段階的に延ばします。設定の開発者ツールでAPI通信回数と受信本文量を確認できます。初回の画面・画像・音声の取得はこの集計に含みません。動画版チュートリアルは廃止し、遊べる練習を残しています。比較条件・計測結果は [通信ベンチマーク](docs/benchmarks/issue-46-network.md) を参照してください。

オセショ様はAI対局で使える代打機能です。`dist/osesho-ai.js` の専用AIで最大5秒考えます。通常は1局1回、開始前の設定で無限にもできます。開発者ツールには自動代打があります。対オセショ様は通常の難易度選択から利用でき、思考5秒・平手・持ち駒あり・盤面崩壊200手、人間は20分＋毎手5秒に固定されます。この対局では代打は1回、無限設定の代わりに3回を選べます。比較条件と評価結果は [benchmarks/results/summary.md](benchmarks/results/summary.md) を参照してください。

## 開発環境

### Dockerで開発する（推奨）

Docker Desktop（Linuxコンテナ）とDocker Composeがあれば、PCへのNode.jsインストールは不要です。リポジトリのルートで実行してください。

```sh
docker compose up -d --wait
```

初回はNode.js 24のイメージを取得します。起動後は http://127.0.0.1:4173 を開いてください。このPCからアクセスできます。
ソースはPC上のファイルを共有します。画面のHTML・CSS・JavaScriptの変更はブラウザの再読み込みで反映し、サーバーが読み込むコードの変更はNode.jsのwatch機能で自動再起動します。変更が反映されない場合は `docker compose restart app` を実行してください。

```sh
# 起動中のコンテナでテスト・ビルド
docker compose exec app npm test
docker compose exec app npm run build

# ログの確認
docker compose logs -f app

# 停止・コンテナの削除（対局データは保持）
docker compose down
```

対局データはDockerの名前付きボリューム `runtime` 内の `/app/.sites-runtime/rooms.sqlite` に保存します。PC側の `.sites-runtime/rooms.sqlite` とは別のデータです。`docker compose down -v` は対局データも削除するため、初期化したい場合だけ使用してください。
ビルド結果はコンテナ内の `.sites-runtime/release/dist` と、PC側にも共有される `dist/server/index.js` に生成されます。

### Node.jsを直接使う

Node.js 24以降。外部npmパッケージは不要です。

```sh
node server.mjs
node --test tests/*.test.js
node build.mjs
```

起動後は http://127.0.0.1:4173 を開いてください。友人対局データは .sites-runtime/rooms.sqlite、AI対局はブラウザのローカルストレージに保存されます。
オンライン公開にはAPIと永続DBを動かすホストが必要です。GitHub Pagesだけではオンライン対局は動きません。

### 友人対局の作成制限

友人対局の新規作成は、同じIPから最初に作成した時点から12時間で100部屋までです。同じWi-Fiや携帯回線などでIPを共有する利用者は、この枠も共有します。再読み込みやトークンの変更、部屋の削除では枠をリセットしません。既存の部屋への復帰・参加・着手・同じ部屋での再試合、およびブラウザ内のAI対局はこの作成数に含みません。

さらに、新規作成を試みる頻度を同じIPで1分5回までに制限します。公開版はWorkersのRate Limitingバインディング `ROOM_CREATE_BURST` を使用し、ローカル版は同じ設定のメモリ内カウンターを使います。Workersの短時間カウンターは拠点ごとの概算ですが、12時間の上限はD1で部屋作成と同じトランザクション内で判定します。制限時はHTTP 429と再試行までの秒数を示す `Retry-After` を返します。追加のブラウザ通信やCookieは必要ありません。

公開版はCloudflareが設定する `CF-Connecting-IP`、ローカル版は接続元ソケットのIPを使います。IPの生値はDBに保存せずハッシュ化し、12時間のカウンターは期限後に5分ごとの清掃で削除します。ハッシュは識別用であり、匿名化を保証するものではありません。公開版でIPやバインディングが欠ける場合は、新規友人対局を503で拒否します。制限判定もWorkerの呼び出しに含まれるため、攻撃時のリクエスト費用を完全に防ぐものではありません。

## 公開と共同開発

本番の設定・検証・通知・復旧手順は [運用手順](docs/production.md) を参照してください。PRとmainの更新ではGitHub Actionsがテストとビルドを実行します。仮広告の箱はローカルプレビューだけに表示します。


### 公開版の開発者ツール

公開版では、設定の「開発者ツール」を初めて開くときに `kamaboko` と入力します。ブラウザ内で比較する簡単なUIロックで、入力・解除による通信やCloudflare側の設定はありません。入力値を保存せず、成功したページを再読み込みするまで入力を省略します。`localhost`・`127.0.0.1`・IPv6ループバックから開くローカルプレビューでは、従来どおり入力不要です。

これは開発者ツールへの誤操作を防ぐ入口です。パスワードは公開ソースに記載しており、秘密を守る認証や、改変したクライアント・ブラウザの開発者コンソールを制限する仕組みではありません。

GitHubの `main` をCloudflare Workers Buildsに接続しています。Pull Requestを確認して `main` に取り込むと、Cloudflareが検査して新しい版を公開します。ビルドコマンドは `npm test && npm run build`、デプロイコマンドは `npx wrangler d1 migrations apply othello-shogi-db --remote && npx wrangler deploy` です。D1データベース `othello-shogi-db` は `DB` に割り当て、初期スキーマは `drizzle/0000_rooms.sql` にあります。設定は `wrangler.jsonc` を参照してください。

変更前に `npm test` と `npm run build` を実行してください。ローカルでは `npm start` で遊べます。既存のChatGPT Sites版は別の公開先で、Cloudflareへ対局データは自動移行しません。

DBのマイグレーションは、Wrangler 4.36.0以降でデプロイ前に適用します。Cloudflare Workers Buildsも次の順で実行する設定です。必要なD1権限を持つCloudflare認証が必要です。

```sh
npx wrangler d1 migrations apply othello-shogi-db --remote && npx wrangler deploy
```

`drizzle/0001_room_creation_limits.sql` は制限用テーブルと索引を追加し、既存の部屋を保持します。`wrangler.jsonc` に短時間制限を設定済みです。`namespace_id` はこのアカウント内で他のレート制限と共有しない専用の値を使ってください。ブラウザ内のAI対局は対象外です。公開版は制限回避を防ぐため旧サーバーAIの新規作成を410で拒否しますが、既存の旧AI対局の取得・復帰は維持します。

作成者の既存部屋の検索には `(host_hash, expires)` の複合索引を使い、有効な1部屋だけを取得します。新規作成直後の取得・参加・着手・定期確認は部屋IDの主キー、期限切れデータの清掃は期限の索引を使います。他の利用者の部屋が増えても、それらを一件ずつ調べる検索を避けます。

存在しない提案の取消や同じ提案の再送など、状態が変わらない操作ではDBを書き換えず、対局のバージョンも増やしません。実際の着手・承諾・取消・時間切れは従来どおり更新します。APIの本文は最大4096バイトで、認証確認後にストリームを読み、サイズ超過時は本文の残りを読み込まず413で拒否します。通常の対局リクエストはこの上限内です。

公開版とローカル版はCSPの `frame-ancestors 'none'` と `X-Frame-Options: DENY` で外部サイトへの埋め込みを禁止します。スクリプト・AI Worker・API通信は同一オリジンに限定し、既存の外部効果音とデータ形式の音声は許可しています。既存のインライン装飾のため、スタイルには `unsafe-inline` を許可します。広告配信サービスを接続する際は、そのサービスに必要なスクリプト・通信・子フレームのドメインだけをCSPに追加してください。自サイトの埋め込みを禁止する `frame-ancestors` は維持します。

## 対局の合間の広告（配信準備）

このブラウザで自分が2勝するごとに、対局を閉じる・新しい対局を作る・再試合に進むタイミングで広告枠を要求します。敗北・引き分け・チュートリアル・開発者モードは数えません。同じ対局の再読み込みや再取得は重複計上しません。カウントはlocalStorageに保存し、追加のAPI通信は行いません。

現在は広告配信サービス未設定です。公開版では広告を出さずに進み、ループバックから開いたローカル版のみ5秒後に閉じられるテスト広告を表示します。実際の広告を接続する際は、`createWinAdBreak({showAd})` に、広告終了・配信なし・エラーのいずれでも完了する非同期処理を渡してください。実配信の終了ボタンと表示時間は広告サービスに任せます。オセショ様の「広告を見る」による報酬とは別の枠です。


### オセショ様の通算勝利数と検索向けページ

固定ルールの対オセショ様戦の勝利対局数をD1に集計します（人数ではありません）。ブラウザからの自己申告であり、不正対策付きの競技ランキングではありません。対局キーで重複を防ぎ、同じ対局を再読み込みしても加算しません。ロビーの集計取得は30分キャッシュ、勝利報告は1局1回で、通常AIや毎手の対局API通信は増えません。ネットワークエラー時は結果画面から再試行できます。

公開前に `npx wrangler d1 migrations apply othello-shogi-db --remote` で `0002_challenge_wins.sql` を適用してください。`npm run deploy` はこの移行を含みます。Pagesの静的ビルドだけではAPI用Worker・DBは更新されません。

`/rules.html` は検索エンジンにも読める遊び方、`/sitemap.xml` は公開ページ一覧です。正規URLは https://oshogi-games.pages.dev/ に統一しています。公開後のクロール・登録・順位は検索エンジン側で決まるため、ビルド成功だけでは検索掲載を確認したことになりません。
